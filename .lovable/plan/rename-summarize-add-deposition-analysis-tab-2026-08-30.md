# Rename Summarize + Add Deposition Analysis Tab

## Goal
Rebrand the current `/summarize` page as a unified document-intelligence workspace, then split it into two tabs: the existing document-search/Ask workflow and a new **Deposition Analysis** view that the user will provide.

## Naming recommendations

| Scope | Option A | Option B | Option C |
|-------|----------|----------|----------|
| **Page name** (sidebar label) | **Doc Intel** | **Doc Magic** | **Workbench** |
| **Route** | `/docs` | `/docs` | `/workbench` |
| **First tab** (current Summarize) | **Doc Search** | **Ask Documents** | **Search & Summarize** |
| **Second tab** | **Deposition Analysis** | **Depo Analysis** | **Transcripts** |

**Recommended combination:** Page = **Doc Intel**, route = `/docs`, tabs = **Doc Search** | **Deposition Analysis**.

- "Doc Intel" is short, professional, and litigation-appropriate (intelligence, not magic).
- "Doc Search" is clearer than "Summarize" because the primary interaction is now search-first.
- "Deposition Analysis" is explicit and lawyer-grade.

## Proposed UI structure

```text
/docs
├── Header: "Doc Intel" icon + title + subtitle
├── Tab bar
│   ├── Tab 1: Doc Search  → existing SummarizeView content
│   └── Tab 2: Deposition Analysis → user-provided component
└── Content area swaps with the selected tab
```

- Tab state can live in URL query param (`?tab=search` | `?tab=deposition`) so deep-linking and browser back/forward work.
- The existing `SummarizeView` component moves under the first tab unchanged; only the route file and surrounding shell get the tab chrome.
- The second tab renders the deposition-analysis code the user provides.
