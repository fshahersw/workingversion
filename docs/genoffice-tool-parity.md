# GenOffice tool and workflow parity

Upstream inspected at [`476e5023c9a4`](https://github.com/genspark-ai/genoffice/blob/476e5023c9a4bc459ca6de7b1d697ab25d94850e/README.md), fetched from `origin/main` for this audit. Original public baseline: `e595931af932`; this expansion follows local commit `d872448f8d63`. The upstream snapshot is dated 2026-09-21; its Git commit timestamp is 2026-09-22. This is a source/handler audit, not certification that every Microsoft Office file renders identically.

**Result:** Writer adds 17 native tools and a 23-operation atomic registry; Slides now covers all 61 documented upstream operation names; Sheets covers all 55 upstream workbook operation names (58 local). PDF adds a real self-hosted PDFium worker and ten native tools. This is substantial capability parity, not complete upstream/desktop equivalence: the qualified and missing capabilities are listed below. Read/write policy, revision checks and native export validation remain authoritative.

## Method and confidence

`scripts/audit-genoffice-tools.mjs` parses actual TypeScript tool declarations (including mapped tool names), the CLI/desktop MCP registries, and the current browser write-mode policies. Run from the repository root with `bun scripts/audit-genoffice-tools.mjs ../references/genoffice`. Its policy intersection is a candidate surface: editor composition hooks and server/provider capability filters can narrow it further. Each row below links the pinned upstream declaration; local equivalents link the current handler declaration when one exists. Names alone do not prove equivalent arguments, export fidelity, or deployment readiness.

| Class | Meaning |
|---|---|
| E | Equivalent capability exists through the current bounded browser/native handler; not byte-for-byte API compatibility. |
| P | Partial capability or an alternative with explicit limits. |
| G | Missing/disabled agent capability; must be implemented and tested before exposure. |
| D | Implemented provider-backed capability; availability depends on deployment/configuration. |

## Changes and remaining work

Implemented: the ports above; browser/native/server tool-policy alignment; bounded workflow guides; native save/download fixes for large archives; per-operation idempotency; session ownership guards; genuine PDF source editing; persistent download links outside the assistant controls. See [integrated acceptance and release checks](./office-native-parity-delivery.md).

Remaining gaps are deliberate and visible in the tables: general media analysis, external PDF image services, PDF paragraph reflow/complex fonts/nested forms/reply creation, some desktop/CLI-only interfaces, Sheets attached-workbook merge, and advanced imported animation/shape compatibility. Multiple new Writer section breaks require intervening Save/reopen; no autonomous agent save tool was added. Remote research tools were not newly integrated in this work.

JEV classifies compact routing questions with a bounded deadline/cache; native code validates IDs, permissions, arithmetic/formulas and operation dependencies. JEV is probabilistic classification, not a deterministic execution engine or a general autonomous subagent. Independent read tools may run concurrently; dependent document writes remain ordered. Bedrock remains the production reasoning provider. See [routing validation](./office-routing-production-validation.md).

Actual Microsoft Office rendering and AWS staging model/IAM/CORS/native-runtime checks are still required. Local synthetic provider runs, native file round trips and a successful Windows production-mode build do not establish those results.
