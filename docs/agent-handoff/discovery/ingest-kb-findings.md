## Actual path and strengths

- Working Set `src/lib/use-pile.ts:1704–1726` submits extracted pages and available original-byte keys to authenticated `saveWorkspaceFn` (`src/lib/kb/workspace.functions.ts:38–40`). Reservations/checkpoints precede work; three documents ingest concurrently (`:234–252`). Small text is synchronous; larger extracted text is queued when configured; textless originals use BDA (`:132–165,258–300`; `ingest-state.ts:84–107`). This is **text-first**, unlike the older BDA-first design document.
- SQS dispatches `kind:text` to the text worker and BDA/reconcile events to the BDA worker (`infra/lambda/kb-ingest/sqs.ts:6–23`). BDA has exact invocation mapping, leased success claims, bounded attempts, owned output-prefix checks, idempotent start tokens, and stale-job reconciliation (`ingest-async.server.ts:523–650,654–730`; `ingest-job-store.server.ts:319–341`). The batch wrapper reports individual failures (`handler-core.ts:14–36`). Source infrastructure defines a 900-second worker, batch size one, and one-minute reconciliation (`infra/app/workflows.cfn.yaml:144,164,191`); deployed configuration is unknown.
- Ready saved-set Ask: `use-pile.ts:1135–1168` → `kb-client.ts:40–52` → authenticated `/api/kb/ask` → `askSavedWorkspace` → Titan query embedding → per-document Aurora hybrid search and Cohere rerank → full chunk fetch → existing single/multi-file writer (`ask.server.ts:94–292`). Review page ranking separately uses `search.functions.ts:47–59` → `searchKbByDocuments`; this branch does not rerank.
- Security strengths: principal derives from Cognito, not the body; workspace lookup checks owner; requested documents and returned chunks must remain within the selection (`ask-selection.ts:17–30`; `ask.server.ts:186–200`). Aurora uses explicit owner/workspace/surface predicates plus transaction-local RLS principal (`aurora.server.ts:156–175,247–285`); migrations enable FORCE RLS (`db/kb/0001_kb_init.sql:226–240`). Actual database role and applied migration state were not checked. Chunk replacement is transactional (`aurora.server.ts:717–775`). These controls should remain deterministic and independent of JEV.
- Answer prompts already distinguish retrieved excerpts from exhaustive review, disallow treating document text as instructions, and disclose reader failures (`pile/ask.server.ts:74–82,255–259,329–335,352–354`). This is a useful foundation; model instruction compliance is not proof of factual completeness.

## Prioritized findings

### P1: BDA output can silently lose content and page provenance

`agents/bda.server.ts:258–259` converts each segment read error to null and skips that segment; the remaining result has no incomplete flag. `:282` prefers consolidated document markdown even when page representations exist. Its fallback `:288` numbers pages from one separately for each segment. `kb/convert.ts:94–124` trusts markers or places unmarked text entirely on page one. `ingest-async.server.ts:595–618` then processes this result as a complete canonical document. A successful subset can therefore be marked ready with missing pages; multiple segments can produce duplicate citation page anchors.

Probes reproduce: two two-page segments become `[1,2,1,2]`; a two-page result with both document and page representations becomes one anchored page; a failed second segment returns the first segment without throwing. These are code counterexamples, not observed AWS output/incident frequencies.

**Fix:** preserve structured per-page identity and segment offsets from the actual BDA contract; require every expected segment and fail/retry transient reads. Validate expected page coverage before ready. Keep unknown/missing pages explicit. Carry table structure and extraction confidence through canonical blocks and chunks. Today chunk input has no confidence field (`chunk.ts:18–27`) and embedding writes `conf:null` (`embed.ts:95`), so the design's confidence-based OCR escalation/ranking is not implemented here. `tablesCsv` is read but the async canonical call only consumes markdown/page count.

### P1: Partially scanned documents can be saved as ready from incomplete text

The client detects empty/poor pages (`use-pile.ts:1700–1708`), but always sends available text (`:1722–1726`). The server lane selector receives readable page count/character count/byte metadata, **not extraction completeness**, and routes any nonempty text through sync/text (`workspace.functions.ts:153–165`; `ingest-state.ts:93–99`). A mixed PDF with one readable page and many scanned pages can be indexed solely from that one page; ready page count reflects the supplied readable pages, not original coverage. `planSaveLane` can say async but that plan is not a transmitted server constraint.

**Fix:** persist original page inventory and per-page extraction state; allow text-first for good pages while queueing OCR for missing/poor pages. Track partial/indexed/failed page coverage separately from document readiness. Require explicit incomplete-coverage disclosure. JEV can prioritize ambiguous quality cases, but deterministic empty-page and known extraction failures must force recovery regardless of classifier opinion.

### P1: Background text ingestion acknowledges transient failures as permanent

`ingest-text.server.ts:259–267` terminalizes any `getPages` error, including transient S3/Dynamo errors, then returns `processed`. `:279–316` also swallows processing or final-checkpoint errors into an error checkpoint. A final checkpoint outage can occur **after** Aurora is ready, yet the document checkpoint becomes error and SQS is acknowledged. BDA's job lease/reconcile path does not cover these text jobs. Save retries skip terminal checkpoints (`workspace.functions.ts:254–255`), and document upsert preserves error status (`aurora.server.ts:360–363`).

Probe: injected transient S3 503 produces terminal error plus successful acknowledgement. **Fix:** common durable job/attempt state for both lanes; distinguish retryable storage/model/throttle errors from malformed input; separate ingestion success from checkpoint reconciliation; acknowledge only durable terminal or completed state. Use receive/job attempts and retry exhaustion rather than converting the first read failure into permanent failure.

### P1/P2: Retrieval outages can masquerade as missing evidence; null embeddings look successful

Per-document search catches Aurora errors and returns empty hits (`search.server.ts:190–201`; Review equivalent `:131–145`). Ask then treats these as unmatched documents or, if all empty, “No relevant passages” (`ask.server.ts:178–182,225–235`). The automatic widening trigger is only fewer than eight total hits (`:154–160`), so several successful documents can mask another document's failed retrieval.

`pile/titan.server.ts:17–22` returns null for non-429/non-5xx HTTP errors and malformed/missing embeddings. `kb/embed.ts:87–98` accepts null as a completed row. Consequently a configuration/auth failure can produce a ready lexical-only index with no degraded status or repair queue. Probe confirms null embedding is accepted; no real auth failure was attempted.

**Fix:** typed per-document retrieval outcomes and embedding health; propagate failed/unavailable distinctly from no match; repair missing vectors asynchronously and publish honest degraded status. Fail closed on malformed vector dimension/nonfinite values. Preserve lexical fallback as an explicitly degraded capability, not an apparently healthy hybrid index.

### P2, latent API/hook issue: source-reuse follow-ups reduce up to 120 chunks to 40

Initial adaptive retrieval allows 120 chunks (`ask-budget.ts:16`). The hook can send reusable prior IDs on follow-up (`use-pile.ts:1143–1158`), but the API takes only 40 (`routes/api/kb/ask.ts:73–77`). Presence of source IDs bypasses all new retrieval (`ask.server.ts:128–134`). Since sources are document-ordered, later documents can disappear from follow-up evidence. A question introducing a new issue would still get only retained old passages. **Current Working Set UI does not enable this branch:** `components/summarize/SummarizeView.tsx:98` fixes scope to auto, and `:244,251` sets followUp only when scope is relevant. Therefore this is a latent API/hook contract defect, not an observed current UI failure; the UI separately lacks its advertised source-reuse follow-up control.

Deposition's saved Ask caller (`use-deposition.ts:1618–1624`) does not send sourceChunkIds or prior, so it does not activate this reuse branch either. **Fix:** one coherent source-set budget and explicit immutable source-set identity/version; retain the relevant prior evidence while retrieving for new requirements. JEV can judge whether the current question is strictly grounded in prior sources or introduces a new issue; uncertainty must widen/retrieve. User intent and membership checks remain authoritative.

### P2: Chunk boundaries do not protect embedding, synthesis, or documented byte limits

The 2,000-character target groups whole paragraphs but does not split an oversized paragraph; the hard cap is 60,000 **characters** (`chunk.ts:40–45,67–80,138–147`). Probe produces one 30,000-character Unicode paragraph occupying 90,000 UTF-8 bytes. This exceeds AWS's documented 64KB result-row boundary; live Data API behavior was not invoked. Titan embeds only the first 8,000 normalized characters (`pile/titan.server.ts:7`); rerank sees at most the first 2,500 from SQL (`aurora.server.ts:251`; `db/kb/0001_kb_init.sql:179`); writers see only the first 3,500, or final multi-file evidence 2,400 (`pile/ask.server.ts:46,217,318`). A decisive clause at the end can thus exist in stored/cited text but never reach the model stages.

**Fix:** sentence/row-aware target splits with repeated table headers and overlap, token and UTF-8 byte ceilings, no silent evidence prefix cuts. Full-chunk fetches also need explicit response-byte batching, since Ask raised the cap while fetch comments still describe about40 chunks (`aurora.server.ts:298–321`). Distinguish actual JSON response mode limits from stale comments before sizing batches.

### P2: Cancel and latency budgets stop short of database and retry layers

HTTP request signal reaches embeddings/rerank/writers, but Aurora `hybridSearch`, `fetchChunks`, `execute` and transaction calls accept no signal (`aurora.server.ts:119–137,156–199,218–239,303–321`). Aurora retry can sleep eight times at three seconds, plus request time (`:48–59`). Aborted embedding is swallowed as lexical fallback (`search.server.ts:71,186`), and already-started database work can continue after disconnect. Embedding retry sleeps likewise do not check cancellation (`embed.ts:45–60`). There is no single end-to-end Ask deadline here.

**Fix:** carry cancellation/deadline through AWS SDK sends and abortable waits, stop scheduling before each stage, never reinterpret abort as missing evidence. Budget query embedding, database, rerank, readers and writer separately under one overall deadline. Preserve durable queued ingestion when a browser disconnects; user-requested ingestion cancellation requires explicit durable job state, not just aborting the browser request.

## Safe speed and JEV plan

1. First fix provenance, partial coverage, typed retrieval failure and durable text retries. Faster classification cannot correct missing or misnumbered evidence.
2. Batch independent TypeSafe heads against the same bounded state: `requires_exhaustive_scan`, `new_issue_vs_prior_sources`, `requires_cross_document_comparison`, `requires_table_or_numeric_analysis`, `extraction_quality_suspect`, and a small retrieval-intent Choice. State includes complete user question, selected document/page inventory, known coverage gaps, prior question/answer summary, source-set identity and explicit user mode. Do not classify full document bodies by default. Deterministic “all/every,” failed extraction, missing pages, explicit mode and cross-document selection requirements veto unsafe cheap routes.
3. Production route must be app → IAM-authenticated AgentCore Gateway → dedicated Lambda TypeSafe adapter → fixed vendor endpoint. Keep key only in adapter Secrets Manager, exact IAM scopes, schema/finite-value validation, bounded total latency, conservative no-opinion/timeout fallback, and cache scoped by principal/workspace/source version/model/rubric. No direct app-to-TypeSafe production bypass. This gateway design remains a proposal; there is no current JEV call in these KB modules.
4. JEV provides probabilistic routing/quality signals, not OCR, embeddings, quote verification, generated answers or authority to omit documents. Keep Bedrock generation and source checks distinct. Parallelize independent per-document retrieval/quality heads; retain dependency ordering for conversion→embedding→commit. Review simpler lookups without per-file generative readers where the evidence suffices, measured against answer quality.
5. Measure stage latency, cache hit rate, successful/failed document retrieval, missing-vector count, indexed/expected pages, cite-page accuracy, follow-up evidence retention, cancellation-to-stop time and exhaustive-scan coverage. Evaluate held-out mixed scans, Unicode/long paragraphs, multiple BDA segments, legal tables, cross-file contradictions, transient failures, stale sources and tenant isolation before rollout.
