## Maintenance constraints

- Keep `.swf-root` styles scoped to the feature. Reuse the host theme and logo; do not transplant the standalone shell or apply global resets. Existing native navigation includes the platform's own Calendarâ€”this is not MCO code.
- Keep server code in `*.server.ts`; no AWS credentials, authenticated connector keys or tool execution in the browser bundle. The only auth-module addition exposes the verified-email claim for reviewer access.
- Definitions are templates/configuration, not trusted authority. The server assigns ownership, enforces current grants, validates the graph, creates immutable runs and records approvals. Do not add an endpoint that trusts a client-supplied completed run or identity.
- Preserve explicit save/conflict behavior and edits made during an in-flight save. Published graph AND mini-app form must remain frozen. New schema fields need import validation, API validation, persistence compatibility, UI and tests.
- Do not reintroduce seeded files, demo teams, mock cases, fallback generated results or fake connector success. Synthetic material is allowed only in isolated tests. Tests must never reach the production AWS account.
- Bedrock analysis covers every source chunk, verifies quotation anchors and rejects truncated/invalid responses. Missing evidence stays unknown. A required unknown condition must fail, not silently route false. Larger workloads must be split explicitly rather than dropping pages/characters.
- The worker processes one step per invocation. SQS is at-least-once. Before adding external writes (email, Box upload, docket actions), design per-step idempotency, explicit confirmation, least privilege and an audit trail; checkpointing alone cannot make a remote side effect exactly once.
- Python must keep a new network-disabled interpreter session per invocation. Never use the existing chat code-interpreter module's process-global session for Workflows.
- Use the native Office creation API and returned `draftId`; the actual editor route is `/office/drafts/$draftId`. Do not introduce a second Word backend.
- Keep Bun test types out of the application compilation. They are loaded only by the separate Workflows test project; otherwise their global fetch types conflict with the platform's existing Node/browser tests.
- No live staging/model/provider checks were performed during code integration. Update validation evidence after real checks, and do not describe a successful local fixture test as a successful AWS integration test.

Priority follow-ups are live service/IAM validation, retention and monitoring ownership, paginated history/library at firm scale, then explicitly scoped additional connectors. The archived original Connections and Research Notes pages remain removed.
